# Авито: кандидатогенерация для поиска услуг

По запросу пользователя нужно отобрать из корпуса (189k объявлений) до 50 кандидатов
для ранжирования. Метрика: recall@50, то есть какая доля выбранных пользователем объявлений
попала в эти 50.

Лучший результат на лидерборде: **0.8258**.

## Как устроено

Решение в два шага.

**Отбор кандидатов** (`src/features.py`). Для каждого запроса набираем около 800 объявлений,
объединяя топы по нескольким сигналам, и сразу считаем для них признаки:

- `ct`: TF-IDF по символьным 3-5-граммам, запрос против заголовка;
- `wt`, `wd`: TF-IDF по словам, по заголовку и по заголовку с параметрами и описанием;
- `cp`: фильтры запроса против параметров объявления;
- `pr`: в каких подкатегориях выбирали объявления по 20 самым похожим запросам из train;
- `emb`: косинус эмбеддингов multilingual-e5-small, дообученной на парах из train;
- `loc`, `dist`: совпадает ли локация и сколько км до центра локации запроса.
  83% выбранных объявлений лежат в той же локации, что и запрос, это самый сильный сигнал.

**Ранжирование** (`src/rank.py`). Четыре модели на этих признаках: HistGradientBoosting,
два LightGBM LambdaRank с разными параметрами и LightGBM-классификатор. Их предсказания
переводим в ранги внутри запроса и усредняем с весами 2:2:1:1.

| Что добавляли | val | LB |
|---------------|-----|----|
| GBM на TF-IDF + локация + prior | 0.8204 | 0.7533 |
| + e5, атрибуты объявлений, LambdaRank, ансамбль | 0.8531 | 0.7880 |
| + дообученная e5 | 0.8721 | 0.8222 |
| + пул на дообученной e5, 4 модели | 0.8749 | 0.8258 |

Подробности и неудачные попытки в [EXPERIMENTS.md](EXPERIMENTS.md).

## Валидация

Разметки для бенчмарка нет, поэтому валидацию собираем из train. Годятся только те пары,
где выбранное объявление есть в корпусе бенчмарка, а таких около 6.6%.

Берем группы (запрос, локация, фильтры) и повторяем пропорции бенчмарка: у 37% групп текст
запроса встречается в остальном train, у 37% есть фильтры. Для остальных 63% текст выкидываем
из train целиком. Prior по подкатегориям и дообучение e5 считаются только по оставшейся части train.

Без подгонки пропорций val расходилась с лидербордом. А признак «сколько раз объявление
выбирали в train» на val давал +0.026 и при этом портил LB: в val правильные ответы по
построению только объявления, которые уже были в train, а в тесте нет.

## Запуск

Данные положить в `data/`: `train.parquet`, `benchmark_items.parquet`, `benchmark_queries.parquet`.

```bash
conda env create -f environment.yml
conda activate avito-candgen

python src/prep_tfidf.py          # cache/tfidf.pkl
python src/finetune_e5.py         # cache/e5-ft/ и cache/emb_items.npy, нужен GPU (~20 мин на 3060 Ti)
python src/features.py val 12000
python src/features.py test
python src/rank.py eval           # метрики на val
python src/rank.py submit         # submissions/answer_ensemble.csv
```

Без GPU вместо `finetune_e5.py` можно запустить `python src/embed.py`, будет обычная e5,
но результат хуже примерно на 0.02. Для GPU нужен torch с CUDA:
`pip install torch --index-url https://download.pytorch.org/whl/cu121`.

Если e5 дообучили уже после того, как посчитали признаки, пул можно не пересчитывать:
`python src/features.py refresh val` и `refresh test` обновят только колонку `emb`.
